# Pokémon Deal Scanner v0.12

Python + SQLite scanner for Pokémon TCG sourcing, local deal discovery, resale evidence, market-quality analysis and small-scale arbitrage, tuned for an Ireland-based buyer.

`VERSION` and `config.yaml` are the canonical version markers. The current production model is **v0.12**.

## What v0.12 is

The scanner separates **card identity**, **market value**, **executability**, **liquidity** and **deal attractiveness** instead of treating every marketplace price as an equal vote.

Current architecture:

`market data -> exact identity -> EU / US / bridge evidence -> scores and route gates -> immutable forecasts -> matured outcomes`

A read-only Streamlit dashboard sits on top of those outputs. The dashboard is a display layer only; it does not recalculate fair value or create alternative BUY rules.

### Core v0.12 rules

- **Exact printing first.** Primary identity is exact Cardmarket `idProduct` plus set/card identity. Ambiguous mappings are blocked, not guessed.
- **English + Near Mint** is the default acquisition target unless a workflow explicitly says otherwise.
- **EU market is primary** for an Ireland-based buyer.
- **US evidence is reference/confirmation**, not an executable Irish buy price.
- **CardTrader is a bridge/exit market**, not a third independent fair-value vote.
- **PCS** = price-confidence score.
- **LQS** = liquidity / probability and speed of sale.
- **ECS** = confidence the modeled exit can actually be achieved.
- **BOS** = quality of a CardTrader/global bridge opportunity.
- **Deal Score / DQS** = acquisition attractiveness, not fair value.
- BUY economics use **landed acquisition cost**, including postage/fees/FX where material.

See [`AGENTS.md`](AGENTS.md), [`docs/SOURCE_ROLE_MATRIX.md`](docs/SOURCE_ROLE_MATRIX.md) and [`docs/MARKET_QUALITY_MODEL.md`](docs/MARKET_QUALITY_MODEL.md) for the canonical guardrails.

## Model validation and empirical memory

v0.12 freezes immutable daily card × date × model-version forecasts and matures outcomes later at:

- T+1
- T+3
- T+7
- T+14
- T+30
- T+90
- T+180

T+7 is the main short-horizon calibration target. Historical predictions are never rewritten using later information, and validation is chronological/walk-forward rather than random train/test splitting.

The next research layer is the SQL/statistics-first **experience store** documented in [`docs/EXPERIENCE_STORE.md`](docs/EXPERIENCE_STORE.md). Comparable-case retrieval, cross-card/set memory and an optional AI critic remain deferred until enough matured evidence exists.

## Web dashboard

The optional dashboard lives at `dashboard/app.py` and is designed for Streamlit Community Cloud.

The **Today** view presents:

- existing `RESELL_TEST`, `WATCH_ONLY`, evidence/revalidation and `NO_EDGE` route signals;
- compact deal cards showing validated buy, modeled net exit, spread, ROI and PCS/LQS/ECS/BOS;
- route and price-band filters;
- a broader **Discovery queue** from `top_flips.csv`, explicitly labelled as pre-route sourcing evidence rather than a final resale recommendation;
- immutable forecasts in a separate audit view.

The hosted page reads `dashboard/data/dashboard_snapshot.json`, a whitelisted public snapshot generated by GitHub Actions. It contains market/model fields only and excludes API keys, personal inventory and seller-level/private data.

See [`docs/DASHBOARD.md`](docs/DASHBOARD.md).

### Run the dashboard locally

```bash
python -m pip install -r requirements-dashboard.txt
streamlit run dashboard/app.py
```

Run the scanner first if you want local SQLite/output data. If no local database exists, the app falls back to the committed hosted snapshot.

## Source roles

| Source | Main production role |
| --- | --- |
| Cardmarket official catalogue / price guide | EU discovery, history and reference |
| Targeted Cardmarket live EN/NM validation | executable acquisition evidence after shipping/eligibility checks |
| eBay sold evidence | resale / realised-value evidence when exact and verified |
| TCGCSV / TCGplayer market data | US/global reference and liquidity context |
| CardTrader | bridge / resale route and marketplace depth |
| Adverts.ie | manual Irish/local discovery and resale context |
| Gumtree | Northern Ireland / UK discovery and arbitrage research |

Active asks are not automatically treated as realised sales. Generic Cardmarket low prices are discovery-only and cannot create an Ireland BUY by themselves.

## Workflow scheduling

The production GitHub Actions workflow targets one full scan per Dublin calendar day once local time has reached **07:00**. Redundant UTC attempts cover Irish DST and GitHub scheduling delays; concurrency plus a daily-success marker prevent duplicate full scans. Manual workflow dispatch remains supported.

The workflow runs tests first, then the scanner and supporting research/report steps. Daily CSV/JSON reports are uploaded as an artifact. The SQLite research state is cached operationally and also backed up through the configured durable backup workflow.

After a successful scan, GitHub Actions exports the safe dashboard snapshot and attempts to publish only that snapshot back to `main`. Failure of the dashboard publish step must not fail the scanner itself.

## Development guardrails

Before changing scanner behavior:

1. Read [`AGENTS.md`](AGENTS.md).
2. Check current `main` and recent commits.
3. Read the relevant model/source documentation.
4. Make the smallest change that solves the problem.
5. Add/update tests for pricing, source-role, mapping, model-validation or workflow changes.
6. Preserve backward compatibility unless a versioned migration is intentional.

Useful commands:

```bash
pytest -q
python scripts/run_daily.py --help
python scripts/export_dashboard_snapshot.py
```
